# Smart Syllabus Generator Web v1.4.0 — JSON Only

## หลักการ

บันทึก/เปิด **JSON เท่านั้น** ไม่มี Draft database และไม่มี Auto Save ใน Browser

- **สร้างใหม่** เริ่มแบบฟอร์มว่าง (จะถามก่อนหากมีการเปลี่ยนแปลงที่ยังไม่ดาวน์โหลด)
- **เปิด JSON** โหลดข้อมูลที่เคยบันทึกไว้ แม้ไฟล์นั้นยังกรอกไม่ครบ/ตรวจสอบไม่ผ่าน
- **บันทึก JSON** ดาวน์โหลด JSON ทุกสถานะ โดยไม่ตรวจสอบก่อนบันทึก (ผู้ใช้ต้องตรวจว่ามีไฟล์อยู่ใน Downloads จริง)
- **ตรวจสอบข้อมูล** แสดงผล Validation โดยไม่ขัดขวางการบันทึก JSON

ใช้ JSON SchemaVersion 1.0.0 และชื่อฟิลด์ชุดเดิม **แต่ไฟล์ที่ยังกรอกไม่ครบอาจไม่ผ่าน JSON Schema** จนกว่าจะแก้ข้อมูลครบ จึงไม่ควรนำเข้า SQL Server / Blazor โดยตรงในสถานะนี้

## ข้อมูลเก่าที่บันทึกผ่าน IndexedDB

ก่อนแทนที่ v1.3.4 **เปิดเว็บเดิม แล้วกด “Draft ของฉัน” และ “สำรอง Draft JSON”** สำหรับ Draft ทุกไฟล์ที่ต้องการเก็บ เพื่อย้ายมา v1.4.0 รุ่นใหม่นี้ไม่ลบ IndexedDB เก่า แต่จะไม่แสดงรายการ Draft ใน Browser อีกต่อไป

## การทำงานสำหรับภาคเรียนต่อไป

1. เปิด JSON จากปี/ภาคเรียนเดิม
2. แก้ปีการศึกษา ภาคเรียน และ Section รวมถึงข้อความที่ต้องปรับ
3. กด “ตรวจสอบข้อมูล” ตรวจรหัสหลักสูตร/PLO/ผู้สอน และข้อมูลทั้ง 6 ส่วน
4. กด “บันทึก JSON” ได้ชื่อไฟล์ใหม่ตามข้อมูลล่าสุด เช่น `SYLLABUS_244442_2570_1_01.json`

**ข้อจำกัด:** Chrome/Edge จะดาวน์โหลดไฟล์ใหม่ ไม่เขียนทับไฟล์ที่เปิดจากเครื่องโดยอัตโนมัติ; อาจตั้งชื่อซ้ำแล้วเติม `(1)`. การ Refresh/ปิดหน้าต่างโดยไม่บันทึก JSON ทำให้ข้อมูลที่แก้ในรอบนั้นสูญหาย

## Deploy

1. แตก ZIP แล้วอัปโหลดไฟล์ `index.html`, `src/app.js`, `tools/build.py` ไปยัง `develop` ในตำแหน่งเดิม
2. Commit: `Switch to JSON-only save and reload v1.4`
3. ทดสอบ Localhost ผ่าน `py -3 -m http.server 8000` ใน root ของโฟลเดอร์
4. เปิด `http://localhost:8000/` (ตรวจว่า UI บอก v1.4.0)
5. ทดสอบบันทึก JSON ที่ไม่ครบ, โหลดกลับ, แก้, ตรวจสอบ, บันทึก, และเปิดหลัง Refresh
6. ยังไม่ต้อง Merge เข้า main

## โครงสร้างข้อมูล

- `SchemaVersion` ยังเป็น `1.0.0`
- `OfferingId` คำนวณจาก `CourseCode`, `Semester`, `AcademicYear`, `Section`; ระหว่างยังกรอกไม่ครบอาจเป็นข้อความว่าง
- ชุด Master ของหลักสูตรและผู้สอนอยู่ใน `data/`; ฝังใน `index.html` เพื่อทำงานแบบ Standalone
- ไม่มี Backend, ไม่เรียก API, ไม่บันทึกข้อมูลขึ้น GitHub
