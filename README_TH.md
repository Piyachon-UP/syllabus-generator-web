# Smart Syllabus Generator — UI v1.3.0

Static Web App สำหรับคณะวิทยาศาสตร์ มหาวิทยาลัยพะเยา — HTML/CSS/JavaScript ทำงานทั้งหมดภายใน Browser โดยไม่ต้องมี Backend สำหรับ Phase 1

## สิ่งที่เปลี่ยนจาก v1.2.0

| ส่วน | v1.3.0 |
|---|---|
| ข้อมูลรายวิชา | ไม่แสดงดอกจัน (*) ทุกช่องกรอกผ่านข้อความ (รวมถึงปี ภาคเรียน และชั่วโมงเรียน); ตรวจสอบความครบถ้วนของทุกช่องเมื่อกด Validate |
| หน่วยกิต | กรอก **3** เท่านั้น (ไม่ใช่ `3(2-2-5)`); เก็บ `Credits: "3"`, `LectureHours: 2`, `LabHours: 2`, `SelfStudyHours: 5` แยกกันใน JSON; จัดรูป `3(2-2-5)` ใน Phase 2 DOCX |
| ผู้สอน | เอา Lecture% / Lab% ออกจากแบบฟอร์มและยกเลิกการตรวจรวมสัดส่วน 100%; เพิ่มตัวเลือก **＋ ไม่พบรายชื่อ / กรอกเอง** พร้อมช่องชื่อและสาขาวิชา |

| การประเมิน | เอารหัสประเมินและหมายเหตุออก; ประเภทประเมินเป็นรายการภาษาไทยที่พิมพ์อื่นได้; รหัส CLO ใช้ช่องข้อความคั่นด้วยจุลภาค |

## วิธีเปิดทดสอบ

1. แตก ZIP ลงโฟลเดอร์ `syllabus-generator-web`
2. เปิด PowerShell ในโฟลเดอร์นั้น แล้วรัน:

   ```powershell
   py -3 -m http.server 8000
   ```

3. เข้า `http://localhost:8000/` ผ่าน Chrome หรือ Edge
4. ทดสอบ Course Info → เลือก PLOs → เพิ่มผู้สอน (ลอง **กรอกเอง**) → เชื่อม CLO/PLO → กรอกแผนบรรยาย/ปฏิบัติ → เลือก A–F หรือ S/U → ตรวจสอบ → ส่งออก JSON
5. บันทึก Draft แล้ว Refresh เว็บเพื่อยืนยันว่าข้อมูลยังอยู่; เมื่อต้องการย้ายไป GitHub Pages ให้ใช้ **เครื่องมือ → สำรอง Draft JSON** และนำเข้าใหม่ใน Origin ปลายทาง

> **อย่ากรอกข้อมูลจริงบนไฟล์เดิมโดยไม่สำรอง JSON** โดยเฉพาะก่อนนำ Version ใหม่ขึ้น GitHub Pages

## การใช้ Dropdown ที่เพิ่มรายการได้

- **ผู้สอน:** รายชื่อ Master เลือกจาก dropdown; หากไม่มี ให้เลือก `＋ ไม่พบรายชื่อ / กรอกเอง` แล้วใส่ชื่อ/สาขาวิชา
- **วิธีสอน / ประเภทประเมิน / ประเภทแหล่งเรียนรู้ / ผู้สอนในแผน:** เป็นช่องข้อความที่ผูกกับ `datalist` ของ Browser; เมื่อคลิกหรือพิมพ์จะมีคำแนะนำให้เลือก แต่ **สามารถพิมพ์ข้อความภาษาไทยอื่น ๆ** ได้ทันที
- **CLO → PLO:** เป็น Dropdown แบบเลือกเพิ่มทีละ PLO; คลิกปุ่ม `PLOx ×` เพื่อนำรหัสออก

## JSON Contract และข้อมูลรุ่นเก่า

**SchemaVersion ยังคงเป็น `1.0.0`** และใช้ฟิลด์ที่มีอยู่ เพื่อให้สามารถนำข้อมูลเข้าสู่ระบบ Blazor ภายหลังได้โดยไม่ต้องแก้สัญญาข้อมูลในครั้งนี้

- `Credits` ยังคงเป็น string แต่เปลี่ยนจาก `"3(2-2-5)"` มาเป็น `"3"`; เมื่อเปิด Draft เก่าที่อยู่ในรูป `3(2-2-5)` โปรแกรมจะแยกตัวเลข 3 ไปเก็บใน Credits โดยชั่วโมงสอนยังอยู่ในฟิลด์เดิม **ไม่เดาค่าชั่วโมงจากสตริง**
- ช่องซ่อน เช่น `LecturePercent`, `LabPercent`, `AssessmentCode`, `BloomLevel`, `LearningActivities` และ `AssessmentMethods` **ยังอยู่ใน Schema เดิม** เพื่ออ่าน Draft รุ่นเก่า และจะไม่ถูกลบออกจากข้อมูลเก่าโดยอัตโนมัติ
- ใน v1.3.0 ใช้ `LecturePlans[].Notes` และ `LabPlans[].Notes` สำหรับ **ชื่อผู้สอนในแผน** เพราะยังไม่ได้เพิ่มฟิลด์ใหม่ใน Schema ดังนั้นเมื่อเปิด Draft รุ่นก่อน ให้ตรวจสอบ `Notes` เดิมด้วย: ข้อความหมายเหตุเก่าอาจไม่ใช่ชื่อผู้สอน
- เมื่อผู้ใช้แก้ช่องหัวข้อ/กิจกรรมรวมใหม่ ข้อความจะจัดเก็บใน `Topic` ส่วน `LearningActivities` จะว่าง (แต่ถ้าไม่ได้แก้ช่องนี้ ข้อมูลรุ่นเก่าทั้งสองส่วนยังอยู่ใน JSON)
- ข้อมูลชื่อจาก Master ไม่มี `StaffId`/`Email` โปรแกรมจึงไม่สร้างขึ้นเอง; การไม่มีรหัสเหล่านี้เป็น **คำเตือน** สำหรับงานเชื่อม REG ในอนาคต
- ตาราง GradeScale จะเพิ่มแถวเกรดพร้อมชื่อ แต่ **ไม่เดาเกณฑ์คะแนน** ให้ผู้สอนระบุเอง
- Browser คนละ Origin เช่น `localhost:8000` กับ `piyachon-up.github.io` จะมีพื้นที่เก็บ Draft คนละชุด

## ไฟล์ในชุด

```text
index.html                       ไฟล์เผยแพร่บน GitHub Pages (standalone)
src/app.js                       Source UI และตรรกะฝั่ง Client
src/styles.css                  รูปแบบหน้าจอ
data/curriculum_plos.json       15 หลักสูตร (Master จากไฟล์ผู้ใช้)
data/instructors.json           100 คน (Master จากไฟล์ผู้ใช้)
schema/syllabus.v1.schema.json  JSON Contract v1.0.0
sample/Smart_Syllabus_Demo.json  ข้อมูลจำลองเดิม
sample/UI_v1_3_*.png            ภาพตัวอย่างหน้าจอ
tools/build.py                   รวม Source + Master + Schema → index.html
tools/test_v13.py               Browser smoke tests
DEPLOY_DEVELOP_TH.md            ขั้นตอนอัปเดต develop
```

หากแก้ไฟล์ `src/` หรือ `data/` ต้อง Build `index.html` ใหม่:

```powershell
py -3 tools/build.py
```

## ข้อจำกัด

- Phase 1 ยังไม่มีการ Generate DOCX (งาน Phase 2)
- ไม่เชื่อม REG View / ไม่มีฐานข้อมูลกลาง / ไม่มีการซิงก์ Draft ระหว่างอุปกรณ์
- เว็บบน GitHub Pages และรายชื่อ Master จะถูกเผยแพร่สาธารณะ โปรดตรวจสอบนโยบายข้อมูลของคณะก่อนอัปโหลด
- Auto Save ที่เรียกผ่าน Browser ขึ้นกับ IndexedDB/localStorage ของ Origin โปรด Export JSON สำรองข้อมูลเป็นระยะ
